# 🔥 FireWatch AI — автоматический наблюдающий за огневыми работами

CV-модуль, который следит за зоной огневых работ (сварка/резка/шлифовка), детектит
**огонь и дым**, проверяет внутри заданной зоны видимые условия наряда-допуска
(**огнетушитель**, **человек-наблюдающий**), и при пожароопасном событии шлёт
**алерт с кадром-доказательством** в Telegram/webhook + пишет в **журнал**.
Есть лёгкий веб-дашборд с живым потоком, статусом зон и редактором зоны.

> Работает на **готовых предобученных весах** (без обучения с нуля). Если реальных
> весов огня нет — система автоматически включает **MOCK-детектор**, чтобы можно было
> сразу увидеть всю логику (зоны → правила → алерт → журнал → дашборд) на демо-ролике.

## Быстрый старт

```bash
cd firewatch

# 1. Окружение и зависимости
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Готовые веса (yolov8n для person + реальные fire/smoke с HuggingFace)
python scripts/download_models.py

# 3. Секреты (для Telegram-алертов) — опционально
cp .env.example .env   # затем впишите TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID

# 4. Запуск сервера + дашборда (по умолчанию — ВЕБ-КАМЕРА)
uvicorn app.main:app
```

Откройте **http://127.0.0.1:8000/** — живой поток с боксами и контуром зоны.
Журнал событий — на **/events**.

### 📷 Веб-камера (источник по умолчанию)

`config.yaml` по умолчанию: `video_source: 0` — камера ноутбука.

> **macOS:** при первом запуске система спросит разрешение **«Камера»** для вашего
> терминала (или разрешите вручную: **System Settings → Privacy & Security → Camera**).
> Запускайте сервер **из своего терминала** — фоновому процессу камеру не выдают.
> Камеру может занять только одно приложение: закройте Zoom/FaceTime/браузер с камерой.

Проверить огонь вживую: поднесите к камере зажигалку/свечу/видео пламени на телефоне —
в зоне появится красный бокс `fire`, полетит алерт и запишется событие.

### 🎬 Офлайн-демо (без камеры и без реального огня)

Синтетический ролик «сварки» + MOCK-детектор огня — гарантированно показывает весь
пайплайн (зона → правило → алерт → журнал), не трогая `config.yaml`:

```bash
python scripts/make_demo_video.py                    # один раз создать ролик
FIREWATCH_VIDEO_SOURCE=data/demo_fire.mp4 FIREWATCH_FIRE_WEIGHTS=mock uvicorn app.main:app
```

Быстрые переопределения источника без правки конфига:
`FIREWATCH_VIDEO_SOURCE=0` (камера) · `=rtsp://...` (IP-камера) · `=data/demo_fire.mp4` (файл).

## Что происходит

1. Кадры читаются из `video_source` (файл или RTSP) и прореживаются до `target_fps`.
2. Детекторы находят огонь/дым, людей и огнетушители.
3. Логика (см. ниже) решает, есть ли **валидное** пожароопасное событие в зоне.
4. При событии: рисуется снапшот, пишется строка в SQLite, летит Telegram/webhook-алерт.
5. Дашборд показывает поток, статус зон и журнал.

### Анти-FP логика (главное против ложных срабатываний)
- Огонь/дым засчитывается, только если **центр детекции внутри зоны**.
- Событие возникает, лишь когда огонь/дым держится **≥ `persistence_frames` кадров подряд** —
  одиночный ложный кадр (искра, блик, закат) **не** создаёт алерт.
- Повтор по той же зоне — не чаще `alert_cooldown_sec` (дебаунс).

## Конфигурация — `config.yaml`

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `video_source` | `data/demo_fire.mp4` | путь к файлу **или** `rtsp://…`, либо индекс веб-камеры (`0`) |
| `target_fps` | `3` | сколько кадров/сек обрабатывать |
| `loop_video` | `true` | зациклить файл (для демо) |
| `models.fire.weights` | `models/fire.pt` | веса огня/дыма; `mock` = демо-детектор |
| `models.person.weights` | `models/yolov8n.pt` | COCO-детектор (класс 0 = person) |
| `models.extinguisher.weights` | `models/ext.pt` | опционально; нет файла → проверка «не проверяется» |
| `detection.conf_threshold` | `0.40` | порог уверенности |
| `detection.persistence_frames` | `4` | сколько кадров подряд для валидного события |
| `detection.alert_cooldown_sec` | `60` | дебаунс повторных алертов |
| `zones` | зона `A` (центр кадра) | полигоны в **нормализованных** координатах 0..1 |

### Поменять зону
- Через UI: на дашборде — **«Задать зону»**, кликами обвести полигон, «Сохранить».
- Или руками в `config.yaml` (координаты нормализованные, 0..1).

### Поменять источник
Отредактируйте `video_source` в `config.yaml` (файл, `rtsp://user:pass@ip:554/...`
или `0` для веб-камеры) и перезапустите сервер.

## Секреты — `.env`

```
TELEGRAM_BOT_TOKEN=...   # у @BotFather
TELEGRAM_CHAT_ID=...     # ваш chat_id
```

Секреты **не** хранятся в `config.yaml` и **не** коммитятся (см. `.gitignore`).
Без них система работает, просто не шлёт Telegram (в лог пишет, что пропускает).
Дополнительно можно задать `alerts.webhook_url` в `config.yaml` — событие
продублируется POST-запросом (JSON).

## Реальные веса огня/дыма

`scripts/download_models.py` качает **реальную** модель fire/smoke с HuggingFace
(`mfranzon/fire-smoke-yolov8`, классы `{0: fire, 1: smoke}`) в `models/fire.pt` —
она и работает по умолчанию на веб-камере/RTSP.

- Если скачать не удалось (нет сети) — система запустится с **MOCK**-детектором,
  чтобы демо всё равно показало весь пайплайн. Свои `.pt` кладите в `models/fire.pt`.
- Форсировать MOCK (для синтетического демо): `FIREWATCH_FIRE_WEIGHTS=mock`.

> Реальная модель обучена на **настоящем** огне/дыме и НЕ ловит мультяшное
> демо-пламя из `make_demo_video.py` — для офлайн-демо используйте MOCK (см. выше).

Для огнетушителя дайте свои веса `models/ext.pt` (напр. модель с Roboflow) —
тогда проверка «огнетушитель в зоне» станет реальной, а не «не проверяется».

## Структура проекта

```
firewatch/
  app/
    main.py         # FastAPI: дашборд + API
    pipeline.py     # цикл: ingest → inference → logic → alert → снапшот/БД
    detectors.py    # обёртки над YOLO (+ MOCK-детектор)
    zones.py        # полигональные зоны, точка-в-полигоне
    rules.py        # правила ПБ, персистентность, дебаунс, состояние
    alerts.py       # Telegram + webhook + снапшоты
    db.py           # SQLite: схема и CRUD событий
    config.py       # загрузка .env / config.yaml
  scripts/
    download_models.py   # скачать веса
    make_demo_video.py   # сгенерировать демо-ролик
    phase0_demo.py       # Фаза 0: инференс + боксы по видео
  models/           # веса (в git не коммитятся)
  snapshots/        # кадры-доказательства
  data/             # демо-видео + SQLite-база
  static/ templates/# фронт дашборда
  config.yaml  .env.example  requirements.txt
```

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | дашборд (поток + статус + редактор зоны) |
| GET | `/video_feed` | MJPEG-стрим обработанного видео |
| GET | `/events` | журнал событий (фильтр по дате/зоне) |
| GET | `/api/status` | JSON статуса пайплайна и зон |
| GET | `/api/events` | JSON событий (`?zone_id=&date_from=&date_to=`) |
| GET/POST | `/api/zones` | получить / сохранить зоны |
| POST | `/api/events/{id}/permit` | привязать наряд к событию |
| POST | `/api/permit/last` | привязать наряд к последнему событию |

## Ограничения MVP

- Проверяются только **видимые** условия наряда (2–3), не весь наряд-допуск.
- Одна камера/источник за раз (мультикамера — позже).
- Готовые fire-веса дают ложные срабатывания на искрах/бликах — лечится порогом,
  персистентностью и дообучением на реальных кадрах площадки (Фаза 3).
